# Write unit + integration tests for async forwarding

## Description
Cover the full forwarding system with automated tests.

Unit tests (tests/unit/bg_thread_test.cpp or new file):
- Future creation, await(), then(), catch() in isolation
- Future state machine: Pending → Resolved/Rejected
- await() on resolved future returns immediately (no yield)
- await() on rejected future throws Lua error
- then() callbacks fire on resolution
- catch() callbacks fire on rejection
- Future with multiple then() calls chains correctly
- Main-thread future await() throws error (test with mock main App)
- Main-thread future await() warns when debug flag is set

Integration tests (tests/integration/ new file):
- Full bg→main forwarding roundtrip:
  1. Register mt_handler for "test_cmd"
  2. Push CommandCall for a command that calls ctx:call_on_main("test_cmd", {}):await()
  3. Wait for ForwardRequest in bg->outbox (test acts as main thread drain)
  4. Execute handler, push ForwardResult to bg->inbox
  5. Wait for CommandResult in bg->outbox
  6. Verify result value
- Full main→bg forwarding roundtrip (call_on_bg):
  1. Register handler for "bg_cmd"
  2. Simulate main thread calling call_on_bg("bg_cmd", {})
  3. Wait for CommandResult in bg->outbox
  4. Verify it's routed to pending_main_futures
- Error forwarding: mt_handler throws erro → ForwardError → catch() fires
- ctx:emit() from bg thread routes through EmitEvent (verify it arrives via drain)
- Queue full: push 65 messages → verifies push returns false
- Coroutine nested await: command calls await(), is resumed, calls await() again
