# Implement Future class with coroutine-based await()

## Description
New src/future.h and src/future.cpp. Single Future usertype registered on both Lua states.

Design decisions (from grill):
- await() on bg thread: calls lua_yield(L, 0) to suspend the running coroutine.
  Run loop manages coroutine ref in pending_yields[callId] — Future never touches the Lua stack.
- await() on main thread: throws Lua error by default.
  Config::debug.futureAwaitOnMainIsError = false downgrades to warning + returns nil.
- then(onResolved, onRejected?): stores sol::protected_function callbacks.
  Invoked inline on the resolving thread during dispatch::drain (no deferred queue).
- catch(onRejected): shorthand for then(nil, onRejected).
- State machine: Pending → Resolved | Rejected. std::atomic<State> for thread-safe reads.
- resolve(json) / reject(json): sets atomic state, invokes stored callbacks.
  Called by bg run loop (for bg futures) or dispatch::drain (for main futures).
- Caller does NOT store coroutine references — Future is purely a handle with callId.
- CallId: std::atomic<uint64_t> counter per Context/App, integer IDs for debug readability.
- Error propagation: rejected await() → lua_error (catchable via pcall).
  catch() callback receives { code, message } table from ForwardError payload.
