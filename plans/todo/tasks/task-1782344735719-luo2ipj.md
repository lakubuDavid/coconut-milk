# Implement dispatch::drain handling for all forwarding message kinds

## Description
In dispatch.cpp drain(), add handling for:

1. ForwardRequest (from bg->outbox, Bg→Main):
   - Parse callId|commandName|jsonArgs
   - Look up in app->commands->mt_handlers (REQUIRED — must be main-thread handler)
   - Execute handler on main thread
   - Push ForwardResult or ForwardError to bg->inbox
   - Signal bg thread via bg->cv.notify_one()

2. ForwardResult (from bg->outbox, Bg→Main for main-thread futures):
   - Look up callId in app->pending_main_futures
   - Invoke then() callbacks inline (we're on main thread, safe)
   - Erase from pending map
   - Never block main thread

3. ForwardError (from bg->outbox, Bg→Main for main-thread futures):
   - Same as ForwardResult but invoke catch() callbacks

4. EmitEvent (from bg->outbox):
   - Parse eventName|jsonPayload
   - Call bridge::emitToJS(app, eventName, payload) on main thread (safe here)
   - (The bg thread ctx:emit() checks is_main_thread flag to route through outbox)

5. CommandResult (from bg->outbox, existing):
   - Route through WebviewTransport::resolveBgCommand() for JS promises
   - Also check if callId matches a pending_main_future (from call_on_bg) — route there instead

6. Reject any unexpected message kinds on wrong queue (e.g., ForwardRequest on main outbox)

Inline callback execution — no deferred callback queue. Re-entrancy is bounded by queue capacity.
