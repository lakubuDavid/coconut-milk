# Refactor API modules into composable init functions (Option A)

## Description
Convert duplicated API module setup (lua_runtime.cpp + bg_thread.cpp) into standalone per-module init functions.

Design:
- Each module gets its own file: src/modules/module_NAME.h + src/modules/module_NAME.cpp
- Each module exports: void init_NAME(sol::state& lua, ThreadKind kind);
- ThreadKind = enum { Main, Background }
- Both init sites call ALL modules in a loop
- Thread-safe modules (fs, json, logging): same impl for both kinds, ignore kind param
- Main-only modules (dialog, notify, clipboard, store, window ctl): install real fns on Main, stubs on Background
- Forwarding stubs (for future use): instead of printing error, push a "forward to main" message to bg->outbox

Concrete steps:
1. Create src/modules/ directory
2. Extract fs module (copy from lua_runtime.cpp / bg_thread.cpp)
3. Extract json module
4. Extract log/info/warn/error module
5. Extract dialog module (real on Main, stub on Background)
6. Extract notify module
7. Extract clipboard module
8. Extract store module
9. Extract window control module (setWindowSize, etc.)
10. Extract views/config/events stubs
11. Add Module registry (optional step — Option B in conversation)
12. Update lua_runtime.cpp to call all modules
13. Update bg_thread.cpp to call all modules
14. Remove duplicated code from both files
15. Write unit tests for each module (stub behavior on bg, real behavior for non-UI fns on bg)
