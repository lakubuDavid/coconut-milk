# Convert bg command execution to lua_newthread + lua_resume

## Description
The bg run loop currently calls handler(params, ctx) via sol::protected_function::operator() on the main Lua thread — cannot yield. Change to coroutine-based execution:

1. lua_newthread(L) to create a dedicated coroutine for each command invocation
2. Push handler function + params + ctx onto coroutine stack via raw Lua C API
3. lua_resume(co, L, nargs)
4. If LUA_YIELD: store {co_ref, timestamp} in Context::pending_yields[callId], continue run loop
5. If LUA_OK: collect return values, push CommandResult/ForwardResult to bg->outbox, luaL_unref
6. If error (LUA_ERRRUN): push CommandResult/ForwardResult with error to bg->outbox, luaL_unref
7. Use luaL_ref to protect coroutine from GC while suspended

ForwardResult/ForwardError handling in run loop:
- Pop message, find callId in pending_yields
- Push result/error value onto coroutine stack
- lua_resume(co, L, 1) — may return LUA_OK (command finished), LUA_YIELD (nested await), or error
- On LUA_OK: collect return values, push to appropriate outbox, luaL_unref

No timeout for stuck coroutines in v1 — bounded by outbox capacity (64).
No generator changes needed — lua_resume is transparent to Lua code.
